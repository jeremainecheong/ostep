Typing: a gradual type system layered on a dynamic language

Python's type hints are a decade-long series of PEPs, not a single design. The runtime does not enforce them — annotations are ordinary expressions stored in __annotations__ — while static checkers read them to prove properties before running. This lesson gives you the lineage, the runtime facts you can rely on, and the 3.13 additions: type-parameter defaults, TypeIs, ReadOnly, @deprecated.

Primary sources: typing module (3.13); PEPs 484, 526, 544, 585, 604, 612, 646, 695, 696, 702, 705, 742; What's New 3.13 ("New typing features"); §3.13 of the reference for annotations. Versions below are the Python-Version field of each PEP.

What you'll be able to do

    The runtime truth

    From the typing docs: "The Python runtime does not enforce function and variable type annotations." Annotations are evaluated when the def/class/assignment executes (in 3.13; PEP 649's deferred evaluation is targeted at 3.14), stored in __annotations__, and otherwise ignored by the interpreter. from __future__ import annotations (PEP 563) stores them as strings instead. typing provides runtime support — generic aliases, get_type_hints(), Protocol machinery — for tools such as type checkers, dataclasses, and validators.

    The lineage

    Core concepts

    Gradual typing & Any

    Unannotated code has type Any, which is compatible with every type in both directions — the escape hatch that lets typed and untyped code mix. object is different: everything is an object, but an object is not usable as an int. Checkers infer types of locals; you annotate boundaries (parameters, returns, attributes).

    Nominal vs structural

    Classes are nominal: Sub is a Base only by inheritance. Protocol (PEP 544) is structural: anything with the right methods conforms, statically — duck typing made checkable. @runtime_checkable lets isinstance check method presence (not signatures). collections.abc types are structural too via __subclasshook__.

    Generics

    PEP 585 made built-ins generic: list[int], dict[str, float] (runtime: a types.GenericAlias whose __origin__ is list; subscription goes through __class_getitem__). PEP 604: int | None builds a types.UnionType, usable in isinstance. PEP 695 (3.12) added syntax — def first[T](xs: list[T]) -> T, class Stack[T]:, type Pairs[K, V] = list[tuple[K, V]] — creating TypeVars implicitly in annotation scopes; variance is inferred. PEP 696 (3.13): defaults, class Box[T = int].

    Narrowing

    Checkers narrow types through isinstance, is None, truthiness, match. User-defined narrowing: TypeGuard[T] (PEP 647) narrows only in the positive branch; TypeIs[T] (PEP 742, 3.13) narrows both branches like isinstance, intersecting with the declared type — "more intuitive" per What's New. assert_never() proves exhaustiveness; reveal_type() asks the checker what it thinks.
