Time series: types, resolution, windows and zones

Time is where DataFrame libraries carry the most machinery: dedicated dtypes, parsing, frequency strings, resampling, rolling windows, calendars and time zones. pandas grew this around the DatetimeIndex; Polars treats datetimes as ordinary typed columns and grouping-by-time as a variant of group_by. Same problems, different defaults — including a resolution change in pandas 3.0 worth memorizing.

Primary sources: pandas Time series / date functionality (3.0 docs: the overview table, resolution note, resampling, offsets, time zones); Polars Parsing, Resampling, Grouping (dynamic/rolling), Time zones.

    Resolution: the 3.0 guide states the default resolution for datetimes and timedeltas is microsecond ("us"), with "s", "ms" and "ns" also supported and dt.as_unit() to change it; to_datetime infers the unit from the string. (pandas 2.x defaulted to nanoseconds — the Pyodide runner below still shows ns.) NaT is the missing marker for all of them. Period represents a span (a month, a quarter); Timestamp a point.

    Polars

    • Date: days since the UNIX epoch (32-bit).
    • Datetime: 64-bit integer since epoch in a chosen unit — ns, us, ms — with an optional time zone in the dtype: Datetime("us", "Europe/Amsterdam").
    • Duration: the difference of two Date/Datetime values (like timedelta).
    • Time: nanoseconds since midnight.

    Parsing: read_csv(try_parse_dates=True), or pl.col("s").str.to_datetime(format) / str.to_date; Parquet carries the types in its schema. Accessors under .dt: year(), truncate(), offset_by(), convert_time_zone(), replace_time_zone(). Missing is null, as always. There is no Period type; use dt.truncate("1mo").

    Resampling and time windows

    pandas: ts.resample("2h").mean() downsamples (groups into bins of the frequency string and aggregates); resample("15min").asfreq() / .ffill() / .interpolate() upsample. Bin edges are controlled by closed, label and origin. Frequency strings are offset aliases — "D", "h", "min", "ME" (month end), "QS", business days "B", custom business days with holidays — and DateOffsets know calendars (friday + BusinessDay() is Monday). Partial-string indexing selects ranges from a DatetimeIndex: ts["2024-03"]. rolling("7D") gives time-based rolling windows; shift, diff, pct_change for lags.

    Polars: group_by_dynamic("t", every="1h", period="2h", offset="30m") groups by dynamic windows: every is how often a window starts, period its length (defaults to every — set it longer for overlapping windows), offset shifts the starts; the guide warns the time column must be sorted ascending or the result is wrong. rolling(index_column="t", period="7d") makes one window per row looking back period. Upsampling is upsample(time_column, every="15m") followed by fill_null(strategy="forward") or interpolate(). Durations use the same string grammar: "1y6mo", "1w", "3d12h", "90s", and calendar-aware dt.offset_by("1mo").

    Time zones

    Both libraries distinguish naive (no zone) from aware values. pandas: tz_localize("UTC") attaches a zone to naive data (interpreting the wall-clock time as that zone); tz_convert("America/Los_Angeles") changes the zone of aware data, keeping the instant. Polars mirrors this exactly: dt.replace_time_zone(tz) sets/unsets/changes the zone label (wall-clock kept); dt.convert_time_zone(tz) converts an aware column to another zone (instant kept). Store and compute in UTC; convert at the edges. Both handle DST ambiguities with explicit options (ambiguous=, nonexistent=).
