Statements: assignment targets, the try machine, and structural pattern matching

Expressions compute; statements bind, branch and clean up. The parts people get wrong are precisely specified: what an assignment target is and how unpacking works, the exact order of try/except/else/finally (and what return inside finally does to a live exception), exception groups with except*, and the pattern kinds of match — each with its own success rule.

Primary sources: §7 (assignment, augmented assignment, del, raise, type) and §8 (try, with, match). PEPs: 634–636 (pattern matching), 654 (exception groups), 3132 (extended unpacking).

What you'll be able to do

    Assignment

    §7.2: an assignment evaluates the expression list (a tuple if there are commas) and assigns the single result to each target list, left to right. Target kinds: a name (bound in the current scope per lesson 3), an attribute reference (obj.attr = v → setattr/__setattr__), a subscription (obj[k] = v → __setitem__; for sequences a negative index is adjusted and must be in range), a slicing (__setitem__ with a slice object), or a parenthesized/bracketed target list — which triggers unpacking: the object must be an iterable with the right number of items, or, with a single starred target, at least as many items as the non-starred targets (the star collects the rest as a list). Augmented assignment (x += 1) evaluates the target once, calls __iadd__ if present (falling back to __add__), and rebinds — so on a tuple element it can both mutate and raise. Annotated assignment (x: int = 1) evaluates the annotation and stores it in __annotations__ (module/class level). del unbinds names or calls __delattr__/__delitem__.

    The try statement, precisely

    §8.4: the try suite runs; on an exception, except clauses are tried in order, the expression being evaluated only when needed, the first match handles it (nested handlers for the same exception: the inner wins). as name is cleared at the end of the clause (to break the frame↔traceback cycle). else runs only if the suite finished normally — no exception, no return/break/continue — and its exceptions are not handled by the preceding excepts. finally runs on every exit; an unhandled exception is temporarily saved and re-raised after it; an exception raised in finally gets the saved one as its __context__; a return/break/continue in finally discards the saved exception.

    Which clauses run?

    raise and chaining

    raise with no expression re-raises the exception currently being handled. raise X from Y sets X.__cause__ = Y (and __suppress_context__); raise X from None hides the context. An exception raised inside a handler automatically gets __context__ set to the one being handled — "During handling of the above exception, another exception occurred". except E as e also lets you e.add_note("…") (3.11+). sys.exception() returns the handled exception.

    except* and exception groups (PEP 654)

    Concurrent code can fail several ways at once, so ExceptionGroup/BaseExceptionGroup wrap a list of exceptions. A try may use except or except*, not both; except*: needs a type. Each except* clause split()s the group: the matching subgroup becomes the handled exception (always wrapped as a group, even a naked one), the rest continues to later clauses; leftovers are re-raised. return, break, continue are not allowed inside except*.

    with: the protocol in six steps

    §8.5 for one item: (1) evaluate the expression to get the context manager; (2) load type(cm).__exit__ for later; (3) call __enter__(); (4) if there is an as target, assign the return value to it — if that assignment fails, __exit__ is still called; (5) execute the suite; (6) call __exit__(type, value, tb) — with the exception if one occurred; a true return suppresses it, otherwise it propagates. Multiple items nest, and 3.10+ allows parentheses across lines.

    match: structural pattern matching (§8.6)

    Evaluate the subject once; try case blocks top to bottom; a pattern succeeds or fails and may bind names; if it succeeds, evaluate the guard (an expression, side effects allowed, only for cases whose pattern matched); the first case with a true guard runs and the statement ends.     type statement (3.12+)

    type Alias[T] = list[T] creates a typing.TypeAliasType; the value is evaluated lazily in an annotation scope (lesson 3). Type parameters can be T, *Ts (TypeVarTuple), **P (ParamSpec), with bounds T: int, constraints T: (int, str), and defaults T = int (3.13, PEP 696).
