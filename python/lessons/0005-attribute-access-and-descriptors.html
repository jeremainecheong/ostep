Attribute access: the algorithm behind the dot

a.x is not a dictionary lookup. It is type(a).__getattribute__(a, "x"), and the default implementation runs a precise five-step search in which descriptors — objects defining __get__/__set__/__delete__ — can intercept. Functions are descriptors; that is how methods bind self. property, classmethod, staticmethod, __slots__: all descriptors. Learn the algorithm once and every "magic" attribute feature is just an application of it.

Primary sources: §3.3.2 (including Implementing Descriptors, Invoking Descriptors, __slots__) and Raymond Hettinger's Descriptor HOWTO, whose pure-Python object_getattribute the simulator below reproduces.

What you'll be able to do

    The three hooks

    • __getattribute__(self, name): called unconditionally for every attribute access on instances of the class. Override it and you own everything — and must call object.__getattribute__(self, name) for anything you need, or you recurse forever. (Implicit special-method lookup may still bypass it — lesson 4.)
    • __getattr__(self, name): called only when normal lookup fails with AttributeError. Must return a value or raise AttributeError. The reference calls the asymmetry with __setattr__ intentional: it keeps the normal path fast and lets __getattr__ read other attributes without recursion.
    • __setattr__ / __delattr__: called on every assignment/deletion. To actually store, call object.__setattr__(self, name, value); assigning self.name = value inside would recurse.

    Descriptors

    Definition (§3.3.2.2): an object attribute with "binding behavior" — any object whose type defines __get__, __set__ or __delete__. A descriptor only works when it lives in a class dictionary (of the owner or a base), not in an instance's __dict__. Defining __set__ or __delete__ makes it a data descriptor; only __get__ makes a non-data descriptor.

    How the call is assembled depends on what you bind through (§3.3.2.3): instance binding a.x → type(a).__dict__['x'].__get__(a, type(a)); class binding A.x → A.__dict__['x'].__get__(None, A); super binding super(A, a).x → find the base B after A in a.__class__.__mro__ and return B.__dict__['x'].__get__(a, A).

    Simulator: object.__getattribute__(a, "x"), step by step

    # the HOWTO's pure-Python equivalent of PyObject_GenericGetAttr (Objects/object.c)
def object_getattribute(obj, name):
    null = object()
    objtype = type(obj)
    cls_var = find_name_in_mro(objtype, name, null)          # walk objtype.__mro__, check vars(base)
    descr_get = getattr(type(cls_var), '__get__', null)
    if descr_get is not null:
        if hasattr(type(cls_var), '__set__') or hasattr(type(cls_var), '__delete__'):
            return descr_get(cls_var, obj, objtype)          # 1. data descriptor
    if hasattr(obj, '__dict__') and name in vars(obj):
        return vars(obj)[name]                               # 2. instance variable
    if descr_get is not null:
        return descr_get(cls_var, obj, objtype)              # 3. non-data descriptor
    if cls_var is not null:
        return cls_var                                       # 4. class variable
    raise AttributeError(name)                               # 5. → __getattr__, if defined

    Everything built on it

    Functions → methods

    A function object has __get__; accessed through an instance it returns a bound method (__self__, __func__); through the class, the plain function. Because functions are non-data descriptors, an instance attribute of the same name shadows the method — the reference notes this is deliberate, so individual instances can acquire different behaviour. staticmethod returns the function unchanged; classmethod binds the class instead of the instance.

    property, slots, __set_name__

    property is a data descriptor, so it always wins over the instance dict — that's how a read-only property blocks assignment. __slots__ creates a member descriptor per name, denies __dict__ and __weakref__ (unless listed or provided by a base), saves memory and speeds lookup; a class attribute with the same name as a slot conflicts (the descriptor would be overwritten). __set_name__(owner, name) is called on every descriptor in the class body when the class is created, so descriptors learn their own attribute name.
