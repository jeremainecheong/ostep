From characters to tokens to expressions

Before the parser sees anything, a tokenizer turns your file into a stream of tokens — and it is the tokenizer, not the parser, that invents INDENT and DEDENT. Then §6 defines what every expression means and in what order it is evaluated. Most "why does Python do that?" questions about arithmetic, comparison chaining and evaluation order are answered by a few paragraphs here.

Primary sources: §2 Lexical analysis and §6 Expressions. The full grammar is §10, generated from Grammar/python.gram. The runners below use the real tokenize and ast modules.

What you'll be able to do

    Logical lines and indentation

    A file is a sequence of logical lines; a logical line may span several physical lines (explicit joining with a backslash, implicit joining inside (), [], {}). Leading whitespace of a logical line computes its indentation level. The rule for tabs: each is replaced by one to eight spaces so that the column becomes a multiple of eight; mixing tabs and spaces in a way whose meaning depends on the tab width raises TabError. The tokenizer keeps a stack of indentation levels: a deeper line pushes and emits INDENT; a shallower line pops until it matches — one DEDENT per pop — and raises an error if it never matches.

    Identifiers and keywords

    Identifiers follow Unicode rules (letters in categories Lu, Ll, Lt, Lm, Lo, Nl, plus _; digits allowed after the first character) and are normalized with NFKC. The 35 keywords are reserved everywhere. Since 3.10 there are also soft keywords, reserved only in context — decided by the parser, not the tokenizer, so match = 3 and type = "x" still work:

    Dashed = soft keywords: match, case, _ (match statement) and type (type statement, soft since 3.12).

    Reserved identifier classes: _* (not imported by from m import *; _ is a soft keyword in case), __*__ ("dunder" system names — don't invent your own), __* (class-private names, mangled to _Class__name).

    Literals

    Strings and bytes

    Prefixes: r raw, b bytes, f formatted, u (no-op), combinable as rb/fr. Adjacent literals concatenate at compile time. Escapes: \n, \xhh, \uXXXX, \N{name}; unrecognized escapes in non-raw strings are kept and emit a SyntaxWarning. f-strings: {expr!r:spec}; {x=} for debugging (prints x= plus repr). Since 3.12 (PEP 701) the quotes may be reused inside replacement fields, fields may contain comments and newlines, and nesting is arbitrary.

    Numbers

    Integers: decimal (no leading zeros except 0), 0b, 0o, 0x; underscores for grouping (1_000_000). No limit on size. Floats: 3.14, 1e10, .5. Imaginary: 3j. A leading minus is not part of the literal — -1 is the unary operator applied to 1, which is why -1 ** 2 is -1.

    Expressions: evaluation order and precedence

    §6.17: Python evaluates expressions left to right — with one twist: in an assignment, the right-hand side is evaluated before the left-hand side. So d[f()] = g() calls g first, then f.

    Two more: the truth-value rule — an object is false if it is None, False, a zero of any numeric type, an empty sequence/collection, or defines __bool__ returning False (else __len__ returning 0). And the call rules of §6.3.4: positional then keyword arguments, *iterable and **mapping unpacking, and a TypeError for a parameter given twice or missing without a default.
