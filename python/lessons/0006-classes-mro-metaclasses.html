Language Reference §3.3.3 Customizing class creation · The Python 2.3 Method Resolution Order (HOWTO)

Classes: how they're built, linearized and customized

A class statement is executable code: it runs a body in a fresh namespace and hands that namespace to a metaclass — usually type — which manufactures the class object. Inheritance is a linearization: the C3 algorithm turns your base classes into one ordered list, the MRO, that attribute lookup and super() both follow. This lesson covers the five steps of class creation, C3 by hand, cooperative super(), and the hooks (__init_subclass__, __set_name__, __mro_entries__, __prepare__) that replaced most reasons to write a metaclass.

Primary sources: §3.3.3 (metaclasses, metaclass determination, __prepare__, class body execution, class object creation), Michele Simionato's MRO HOWTO, and §3.3.4 for __instancecheck__/__subclasscheck__ (PEP 3119 ABCs).

What you'll be able to do

    The five steps of a class statement

    Metaclass determination (§3.3.3.3). No bases and no explicit metaclass → type. An explicit metaclass that is not an instance of type (any callable) → used directly. Otherwise → the most derived metaclass among the explicit one and type(base) for all bases; it must be a subtype of all of them, or TypeError (metaclass conflict).

    C3 linearization: the MRO

    The rule (HOWTO): L[C(B1…BN)] = C + merge(L[B1], …, L[BN], [B1…BN]). Merge: take the head of the first list; if it is not in the tail of any other list, append it to the result and remove it from all lists; otherwise try the head of the next list. If no head qualifies, the hierarchy is inconsistent and Python refuses to create the class. Two guarantees follow: local precedence order (a class precedes its parents, and parents appear in the order written) and monotonicity (a subclass's MRO never reorders its parents' MROs).

    C3 by hand

    Edit the hierarchy (one class per line: Name(Base1, Base2); object is implicit). The linearizer runs the merge and shows each step.

    super() is a proxy along the MRO

    super() in a method is super(__class__, self): it looks up attributes starting after the current class in type(self).__mro__ — not in "the parent". That is why cooperative multiple inheritance works: every class calls super().method(), and the MRO decides who is next, including siblings the author never knew about. The compiler provides the __class__ cell (the reference: a class body using super or __class__ gets a __classcell__, which the metaclass must pass through to type.__new__).

    Customization without metaclasses

    __init_subclass__ (PEP 487)

    A classmethod on the parent called whenever a subclass is created, receiving the class keyword arguments (minus metaclass). Registries, validation, defaults — most historical metaclass uses. Always call super().__init_subclass__(**kwargs).

    __mro_entries__ (PEP 560)

    If a base is not a class, Python asks it for __mro_entries__(bases) and substitutes the result — this is how class C(Generic[T]) and class P(Protocol) work without the typing objects being real classes. The originals are kept in __orig_bases__.

    Metaclasses proper: __prepare__ and __new__

    When you truly need to intercept creation: __prepare__(name, bases, **kw) returns the namespace mapping the body executes in (default: a fresh dict; since 3.7 ordinary dicts preserve order, so the old "ordered namespace" use is gone). Meta.__new__(mcls, name, bases, ns, **kw) creates the class — type.__new__ does the heavy lifting (sets __module__, __qualname__, computes the MRO, calls __set_name__ on descriptors, then __init_subclass__ on the parent). Meta.__call__ controls instance creation (singletons). ABCs use a metaclass for register() and the virtual-subclass hooks __instancecheck__/__subclasscheck__ (§3.3.4) that make isinstance(x, Iterable) true for anything with __iter__.
