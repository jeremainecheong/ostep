Selecting data: label/position indexers vs expressions in contexts

In pandas you index: [], .loc (labels, inclusive slices) and .iloc (positions, exclusive slices), each with its own rules for what a scalar, list, slice, boolean array or callable means. In Polars you describe: an expression is a lazy, composable transformation, and a context — select, with_columns, filter, group_by — decides how its result is used. Both approaches select the same data; the mental models are different enough that this lesson gives them their own rules and a Rosetta table.

Primary sources: pandas Indexing and selecting data (the "Different choices for indexing" list, selection by label/position/callable, boolean indexing, query(), where()); Polars Expressions and contexts and Expression expansion.

What you'll be able to do

    pandas: three indexers, one set of rules

    From the guide. .loc is primarily label based (5 means the label 5, not the 5th row) and raises KeyError for missing labels; label slices are inclusive at both ends. .iloc is primarily integer position based (0 to length−1), with Python's usual exclusive slices, and raises IndexError when out of bounds (slices are allowed to run past the end, like Python). Both accept: a single value, a list/array, a slice, a boolean array (NA treated as False), or a callable receiving the object. [] on a DataFrame selects columns for a label or list, but a slice in [] selects rows. Scalars reduce dimension; lists keep it (df["a"] is a Series, df[["a"]] a DataFrame).

    Polars: expressions and the four contexts

    An expression is a lazy representation of a data transformation — pl.col("weight") / (pl.col("height") ** 2) computes nothing until a context runs it. Contexts:

    • select — evaluates expressions over columns and returns only their results. All results must have the same length, or be scalars, which are broadcast (a literal like 1 too). Expressions in one context are evaluated in parallel, independently of each other.
    • with_columns — like select, but keeps the original columns and adds/replaces; therefore results must match the frame's height.
    • filter — keeps rows where Boolean expressions are true (nulls are dropped).
    • group_by (+ agg) — groups by the unique values of one or more grouping expressions (they can be computed, e.g. (pl.col("year") // 10) * 10), then applies aggregating expressions per group. Also group_by_dynamic and rolling (lesson 19).

    Expression expansion makes one expression stand for many: pl.col("a", "b"), by dtype pl.col(pl.Float64), by regex pl.col("^.*_kg$") (must start with ^ and end with $), pl.all(), .exclude(...), and the polars.selectors module (cs.numeric(), cs.starts_with("t")); rename the outputs with .name.suffix("_x") / .alias(). Names must be unique in a frame, so expanding without renaming into a clash is an error.
