# Verified facts — Java 21 course

## JEP 444 Virtual Threads (text fetched from bugs.openjdk.org/browse/JDK-8303683, 2026-09-04)
- Finalized in JDK 21 (previews: JEP 425 in 19, JEP 436 in 20). Changes from 20: virtual threads always support thread-locals; threads created via Thread.Builder are monitored by default (jdk.trackAllThreads).
- Goals: thread-per-request style scaling with near-optimal hardware utilization; minimal-change adoption; tooling. Non-goals: remove platform threads; change the concurrency model; new data-parallelism construct.
- Little's Law: concurrency = throughput × latency (example: 50 ms latency, 200 req/s ⇒ 10 concurrent; 2000 req/s ⇒ 100).
- Virtual thread = java.lang.Thread not tied to an OS thread; M:N scheduling (green threads were M:1; platform threads 1:1).
- Example: 10,000 tasks sleeping 1 s: virtual threads ~10,000 tasks/s; newFixedThreadPool(200) ~200 tasks/s; 1,000,000 tasks → ~1,000,000 tasks/s.
- "Virtual threads are not faster threads" — scale (throughput), not speed (latency). Help when tasks > a few thousand AND not CPU-bound.
- Never pool virtual threads; limit concurrency with semaphores; beware ThreadLocal caching of expensive resources.
- Scheduler: work-stealing ForkJoinPool in FIFO mode; parallelism = available processors (jdk.virtualThreadScheduler.parallelism); maxPoolSize (jdk.virtualThreadScheduler.maxPoolSize) for compensation when a carrier is captured (filesystem ops, Object.wait()); distinct from the common pool (LIFO). No time sharing.
- Carrier: platform thread running the virtual thread; no affinity; carrier identity/stack/thread-locals invisible to the virtual thread; native code sees the same OS thread.
- Mount/unmount on blocking JDK operations (I/O, BlockingQueue.take); LockSupport park/unpark supports virtual threads.
- Pinning: inside synchronized blocks/methods, or native methods/foreign functions → blocks the carrier; scheduler does NOT compensate; use ReentrantLock for frequent long-I/O guards; diagnostics: JFR jdk.VirtualThreadPinned (enabled by default, threshold 20 ms), -Djdk.tracePinnedThreads=full|short.
- Stacks live in the heap as stack chunk objects, grow/shrink; not GC roots (not traversed in STW pauses by G1); G1 humongous limitation: stack reaching half a region (as small as 512 KB) may StackOverflowError.
- API: no public constructors for virtual threads; always daemon; fixed NORM_PRIORITY; placeholder thread group "VirtualThreads"; Thread.Builder, Thread.ofVirtual(), Executors.newVirtualThreadPerTaskExecutor(), newThreadPerTaskExecutor.
- Thread dump: jcmd <pid> Thread.dump_to_file -format=json; doesn't pause the app. JFR events: VirtualThreadStart/End (off by default), VirtualThreadPinned, VirtualThreadSubmitFailed. ThreadMXBean covers platform threads only. JNI IsVirtualThread.
- java.io Buffered*/Print* use explicit locks instead of monitors to avoid pinning; smaller default buffers.
- -XX:+PreserveFramePointer drastically hurts virtual-thread performance.
- Alternatives rejected: async APIs, async/await coroutines, a new user-mode-thread class (Thread.currentThread() pervasiveness).

## JEP 439 Generational ZGC (text fetched from bugs.openjdk.org/browse/JDK-8272979)
- ZGC (JEP 333, production since JDK 15 via JEP 377): concurrent, pause times in microseconds (G1: ms to s), independent of heap size (hundreds of MB to multi-TB). Non-generational ZGC stores young and old together → must collect everything each cycle.
- Goals: young/old generations collected independently, concurrently; preserve pauses < 1 ms, heap sizes, minimal config (no generation sizes, thread counts, tenuring). Non-goal: reference processing in young gen. Cassandra example: 1/4 heap, 4× throughput, pauses < 1 ms.
- Mechanisms: colored pointers (64-bit; metadata in LOW bits in generational, address in high bits; one shift on x64 checks "good" and strips color); LOAD barriers now only strip metadata and update stale (relocated) pointers; STORE barriers (new) add color, maintain the remembered set (old→young pointers) and do SATB marking (report the overwritten value). Act-once property per field between marking phases. Fast-path (JIT inlined) / medium-path (store barrier buffer) / slow-path (C++). Barrier patching (immediates patched at phase change).
- Removal of multi-mapped memory (used to triple-report heap usage; limited heap to 16 TB); "colorless" pointers on stacks/registers.
- Double-buffered remembered set BITMAPS per old region (precise, swapped at each young collection start; no fence unlike card tables such as G1's, 512-byte cards).
- Two-pass young collection (mark, then relocate) → no pre-reserved to-space; can compact in place; dense regions aged in place (survivor or promoted); large objects can be allocated in young gen.
- Old-gen collection: young→old pointers found by running a young collection with old marking; explicit System.gc() runs an extra young collection promoting everything first.
- JDK 21: ZGC has two modes; -XX:+UseZGC -XX:+ZGenerational selects generational (default false in 21; JEP 474 flips default in 23; JEP 490 removes non-generational in 24).

## JEP 441 Pattern Matching for switch (fetched from bugs.openjdk.org/browse/JDK-8300542)
- Lineage: JEP 406 (17) → 420 (18) → 427 (19) → 433 (20) → 441 final in 21. Final changes: parenthesized patterns removed; qualified enum constants allowed as case constants. Builds on JEP 394 (instanceof patterns, 16), JEP 361 (switch expressions, 14); co-evolved with JEP 440 record patterns.
- Selector type: integral primitive except long (char, byte, short, int), or ANY reference type. (Legacy: those + boxed forms, String, enums.) Primitive patterns for boolean/long/float/double are future work.
- Grammar: case Constant{, Constant} | case null [, default] | case Pattern [when Guard] | default. Guards only on pattern labels.
- First applicable label wins (no best fit). Dominance: a label dominated by an earlier one is a compile error (e.g. case CharSequence cs before case String s). Unguarded pattern dominates the same guarded pattern; guarded dominates only if guard is constant true; pattern label dominates constant labels of its type (case Integer i dominates case 42). Suggested order: constants → guarded patterns → unguarded patterns. Only one match-all label (default / unconditional pattern) allowed.
- Exhaustiveness required for switch expressions and for switch statements that use patterns/null labels or non-legacy selector types; type coverage; sealed hierarchies (permits) count; generic sealed refinement; compiler synthesizes a default that throws for separate-compilation drift. MatchException thrown when no label applies at run time or a record accessor throws in a pattern; enum switch expressions now throw MatchException instead of IncompatibleClassChangeError.
- null: case null matches null; without it → NullPointerException (default does NOT match null); case null, default combined label; error to have both that and a default.
- Pattern variable scope is flow-sensitive: includes the guard, the rule body; fall-through into/through a label declaring a pattern variable is a compile error; multiple patterns per label not allowed.

## JLS SE 21 Chapter 17 Threads and Locks (fetched from docs.oracle.com)
- 17.1 monitors: every object has a monitor; synchronized statement locks the computed object; synchronized instance method locks this, static locks the Class object; unlock on any completion; reentrant (each unlock reverses one lock). Deadlock neither prevented nor detected.
- 17.2 wait sets: wait requires holding the lock (else IllegalMonitorStateException); releases all n locks, waits until notify/notifyAll/interrupt/timeout/spurious wake-up ("permitted although not encouraged" → wait in loops), re-locks n times; interrupt → InterruptedException with status cleared. notify picks an arbitrary thread; notifications cannot be lost due to interrupts.
- 17.3 sleep/yield have NO synchronization semantics; `while(!done) sleep` with non-volatile done may never terminate.
- 17.4 memory model: describes allowed behaviours; compiler/CPU may reorder when single-thread semantics are preserved (Table 17.4-A: r2==2 && r1==1 possible). Shared memory = fields, static fields, array elements; locals/params/handler params never shared. Conflicting accesses = same variable, at least one write.
- Actions: read/write (normal), synchronization actions (volatile read/write, lock, unlock, thread first/last action, thread start/termination detection), external, thread divergence.
- Synchronization order: total over synchronization actions. synchronizes-with: unlock→subsequent lock on same monitor; volatile write→subsequent reads of v; thread start→first action; default-value writes→first action of every thread; final action of T1→any action detecting T1 terminated (join/isAlive); interrupt→detection. Source = release, destination = acquire.
- happens-before: program order; constructor end → finalizer start; synchronizes-with; transitive. Derived: unlock hb subsequent lock; volatile write hb subsequent read; start() hb actions in thread; all actions hb return from join(); default init hb everything.
- Data race = conflicting accesses not ordered by hb. Correctly synchronized ⇔ all SC executions race-free; then all executions appear sequentially consistent. hb does not force actual ordering if unobservable. Reads may see later writes (Table 17.4.5-A r1==r2==0); causality/out-of-thin-air (Table 17.4.8-A) prevented by commit-based causality requirements.
- 17.5 final fields: freeze at constructor exit; a thread that sees a reference only after construction sees final fields correctly initialized (and objects reachable through them at least as up to date), even via a data race — enables immutable objects without synchronization (FinalFieldExample: f.x guaranteed 3, f.y could be 0; String security example). Don't publish `this` from the constructor. Reflection changes → freeze after each; constant-expression finals are inlined. System.in/out/err are write-protected, treated as normal fields.
- 17.6 word tearing forbidden: fields/array elements are distinct (adjacent byte updates must not interfere).
- 17.7 non-volatile long/double writes may be two 32-bit halves; volatile long/double and all reference reads/writes are atomic.

## JLS SE 21 Chapter 12 Execution (fetched)
- Startup: load initial class → link (verify, prepare, optionally resolve) → initialize → invoke main (public static void main(String[] / String...)).
- Loading errors (LinkageError subclasses): ClassCircularityError, ClassFormatError, NoClassDefFoundError (+OutOfMemoryError). Class loader consistency: same name → same Class; delegation returns the same Class for supertypes/field/param/return types.
- Linking = verification (VerifyError), preparation (create static fields with DEFAULT values — initializers run in initialization, not preparation; method tables), resolution (lazy or eager; errors: IllegalAccessError, InstantiationError, NoSuchFieldError, NoSuchMethodError; UnsatisfiedLinkError for natives) — errors thrown only where the program might require the linkage.
- 12.4.1 initialization triggers: instance creation; static method invoked; static field assigned; static field used that is NOT a constant variable. Superclasses initialized first; superinterfaces only if they declare default methods; interface init does not init superinterfaces; a static field reference initializes only the declaring class (Sub.taxi example prints "1729" without "Sub "). Reflection may trigger. Examples: "Super Two false"; J.i (constant) doesn't init I; K.j inits J only.
- 12.4.2 procedure: per-class init lock LC; states: verified+prepared / in progress by thread T / initialized / erroneous. Recursive request by same thread completes normally; another thread's in-progress → wait; erroneous → NoClassDefFoundError; steps: mark in-progress; init constant variables; init superclass then default-method superinterfaces (enumeration order); assertion status; run static initializers in textual order as a single block; success → initialized + notify; exception → wrapped in ExceptionInInitializerError unless it's an Error → erroneous.
- 12.5 instance creation: allocate space for all instance vars incl. superclasses (OutOfMemoryError) → default values → constructor: (1) bind params (2) this(...) → recurse, then step 5 (3) super(...) explicit/implicit → recurse (4) instance initializers & field initializers in textual order (5) rest of body. Dynamic dispatch NOT altered during construction (Example 12.5-2 prints 0 then 3). Implicit instance creation: string literals (interning), boxing, non-constant string concatenation, lambdas/method refs.
- 12.6 finalization may be disabled in 21 (deprecated for removal); no timing/thread/order guarantees; exceptions ignored; constructor completion hb finalize. 12.7 unloading only when the defining loader is reclaimable; bootstrap classes never unloaded. 12.8 program exit: all non-daemon threads terminate + shutdown hooks; System.exit; Runtime.halt (no hooks).

## JVMS SE 21 Chapter 2 (fetched from docs.oracle.com)
- Abstract machine; memory layout, GC and JIT are implementation choices. Primitive types: byte 8-bit, short 16, int 32, long 64 (two's complement), char 16-bit unsigned UTF-16 code unit (default '\u0000'), float/double IEEE 754 binary32/64 (2019 standard since SE 15; strict evaluation always since SE 17; ACC_STRICT unassigned for major > 60); boolean has no dedicated instructions (compiled as int; boolean arrays via baload/bastore, 1 byte per element in HotSpot); returnAddress for jsr/ret. Float parameters: N=24/53, K=8/11, Emax +127/+1023, Emin −126/−1022. NaN unordered; NaN != NaN true; ±0 compare equal but 1.0/0.0 vs 1.0/−0.0 differ.
- Reference types: class, array, interface; null has no run-time type; null encoding not mandated.
- Run-time data areas: per-thread pc register (undefined in native methods) and JVM stack (frames; may be heap-allocated, non-contiguous; StackOverflowError / OutOfMemoryError) and native method stacks; shared heap (GC; OOME) and method area (per-class structures incl. run-time constant pool; logically part of the heap).
- Frames: created per invocation; local variable array (size from Code attribute; long/double take two slots; instance methods: local 0 = this) + operand stack (max depth compile-time; long/double count 2) + reference to the run-time constant pool (dynamic linking = symbolic → concrete, lazily). Normal completion pushes the return value onto the invoker's operand stack; abrupt completion discards the frame.
- Objects: no mandated layout (handles mentioned as one Oracle implementation).
- Special methods: <init> (instance init, invoked only by invokespecial on an uninitialized instance), <clinit> (static, no args for version ≥ 51.0). Signature-polymorphic: MethodHandle/VarHandle methods with single Object[] param, ACC_VARARGS|ACC_NATIVE.
- Exceptions: precise; handlers searched in table order of the current method then up the chain; uncaught → thread's handler / ThreadGroup.uncaughtException. Asynchronous exceptions may be delayed to control-transfer points.
- Instruction set: one-byte opcode + operands (big-endian); only tableswitch/lookupswitch pad to 4-byte alignment. Typed mnemonics i/l/f/d/a (b/s/c only for array and push forms); boolean/byte/char/short computed as int (category 1; long/double category 2). Integer ops never signal overflow; idiv/ldiv/irem/lrem throw ArithmeticException on zero divisor; floating ops never throw (infinity/NaN/subnormal). Rounding: round to nearest (ties even) except d2i/f2i… and frem/drem (toward zero). Widening i2l i2f i2d l2f l2d f2d; narrowing i2b i2c i2s l2i f2i f2l d2i d2l d2f (NaN→0, saturating).
- Invocation: invokevirtual (virtual dispatch), invokeinterface, invokespecial (<init>, private, super), invokestatic, invokedynamic (call site bound once by a bootstrap method; unique linkage state per occurrence). Returns: ireturn (boolean/byte/char/short/int), lreturn, freturn, dreturn, areturn, return.
- Synchronization: ACC_SYNCHRONIZED methods enter/exit the monitor implicitly; monitorenter/monitorexit for blocks; structured locking rules optional to enforce.

## JVMS SE 21 Chapter 5 Loading, Linking, Initializing (fetched from docs.oracle.com)
- Run-time constant pool: symbolic references (class/field/method/interface method/method handle/method type/dynamic constant/invokedynamic call site) + static constants (String constants are interned; numeric). Loadable entries → ldc family.
- Startup: initial class loaded by bootstrap or user-defined loader, linked, initialized, then public static void main(String[]) invoked.
- Loading: class loaders — bootstrap (JVM) and user-defined (ClassLoader subclasses; loadClass → defineClass or delegate). Defining loader vs initiating loader(s); a class is identified by <name, defining loader>; run-time package = package name + defining loader. Array classes created by the JVM (defining loader of the component type). ClassNotFoundException → NoClassDefFoundError; ClassFormatError; UnsupportedClassVersionError; ClassCircularityError; IncompatibleClassChangeError (superclass is interface/final, PermittedSubclasses violations, overriding final). Loading constraints ensure N^L1 = N^L2 across loaders (LinkageError otherwise). Well-behaved loaders return the same Class for the same name.
- Modules/layers: run-time module bound to one loader; unnamed module reads everything and exports everything; access control by run-time module.
- Linking = verification (VerifyError; structural constraints of §4.9/4.10) + preparation (create static fields with default values; impose loader constraints on overriding methods) + resolution (lazy or eager; results/errors memoized; invokedynamic call-site resolution is per instruction). Constraints: loaded before linked; verified & prepared before initialized; errors thrown where the program uses the class.
- Resolution algorithms: class/interface (load via D's defining loader, then access control); field lookup (C, then superinterfaces recursively, then superclass); method lookup (C then superclasses; then maximally-specific superinterface methods; private/static interface methods ignored; signature-polymorphic special case; NoSuchMethodError); interface method resolution (C, then Object public non-static, then maximally-specific…). Access control: public + same module or exported/read; package-private same run-time package; protected subclass rules; private nestmates (NestHost/NestMembers, JDK 11).
- Method handles: 9 kinds (REF_getField … REF_invokeInterface) with bytecode behaviors and method descriptors; bootstrap methods for invokedynamic/condy: args = (Lookup, name, type/descriptor, static args); called via invokeWithArguments; result must be a CallSite of the right type (BootstrapMethodError otherwise); concurrent bootstraps — one result wins.
- Method overriding (5.4.5): same name+descriptor, not private, mA public/protected or package-private in same run-time package (transitive rule). Method selection (5.4.6) for invokevirtual/invokeinterface: private resolved method is selected; else C's declaration that can override, then superclasses, then a unique non-abstract maximally-specific superinterface method.
- Initialization triggers (5.5): new/getstatic/putstatic/invokestatic referencing C (the declaring class of the resolved member); first invocation of a REF_getStatic/putStatic/invokeStatic/newInvokeSpecial method handle (so the bootstrap class is initialized on invokedynamic resolution); reflection; initialization of a subclass; a class implementing an interface that declares a default method; initial class. Procedure with per-class init lock LC: 12 steps — in progress by another thread → wait; recursive → return; erroneous → NoClassDefFoundError; set ConstantValue finals; initialize superclass then superinterfaces declaring default methods (recursively); run <clinit>; on exception wrap non-Error in ExceptionInInitializerError, mark erroneous. Lock elision allowed if happens-before preserved.
- Termination: System.exit/Runtime.exit after shutdown hooks; Runtime.halt; external events. JVM does not terminate automatically when the last non-daemon thread ends (that is the launcher's behaviour via JNI); daemon vs non-daemon.
