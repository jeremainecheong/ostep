Types, values, variables: what Java promises about every value

Java is statically and strongly typed: every variable and every expression has a type known at compile time, and the specification fixes the exact size and behaviour of each primitive on every platform. This lesson covers the two kinds of types (primitive and reference), the conversions the compiler is allowed to insert, and the arithmetic rules that produce the classic surprises — Integer identity, integer overflow, 0.1 + 0.2, and the sign of %.

Primary sources: JLS ch 4 (§4.2 primitive types and values, §4.3 reference types, §4.12.4 final variables, §4.12.5 initial values), ch 5 (widening/narrowing, boxing §5.1.7, numeric promotion §5.6), ch 15 (§15.17 multiplicative operators, §15.18.1 string concatenation).

    Everything else is a reference type: classes, interfaces, arrays, type variables — and the value of a reference-typed variable is a reference to an object or null. Fields, static fields and array elements get the defaults above (§4.12.5); local variables have no default and must be definitely assigned before use (ch 16). A constant variable (§4.12.4) is a final primitive or String initialized with a constant expression; its uses are inlined at compile time — which is why changing one requires recompiling its users (lesson 9) and why reading one does not trigger class initialization (lesson 2).

    Conversions the compiler may insert

    §5.1: widening primitive (byte→short→int→long→float→double, char→int; never loses magnitude, may lose precision for int→float / long→double) is implicit; narrowing (the reverse; truncates bits) requires a cast — except that an int constant expression may be assigned to byte/short/char if it fits (§5.2). Boxing/unboxing (§5.1.7–5.1.8) between primitives and wrappers is implicit; unboxing null throws NullPointerException. Widening reference (subtype → supertype) is implicit; downcasts are checked at run time (ClassCastException). Each context (assignment, invocation, casting, numeric, string) permits a fixed set of these.

    Is the conversion allowed?

    §5.1.7, the boxing identity guarantee: boxing an int, short, char or byte value between −128 and 127 (and any boolean) always yields the same object: a == b. Outside that range the result "may or may not" be the same object — HotSpot's Integer.valueOf caches exactly that range by default. So compare wrappers with equals, never ==.

    Arithmetic, precisely

    • Binary numeric promotion (§5.6): if either operand is double → double; else float → float; else long → long; else int. So byte + byte is an int and needs a cast to store back; char + 1 is an int; 1/2 is 0.
    • Integer division and remainder (§15.17.2–3): division truncates toward zero; % satisfies (a/b)*b + a%b == a, so the remainder has the sign of the dividend: -7 % 3 == -1 (Python gives 2). Division by zero on integers throws ArithmeticException; on floating point yields ±Infinity or NaN.
    • Overflow wraps silently: Integer.MAX_VALUE + 1 == Integer.MIN_VALUE; Math.addExact throws instead. Math.abs(Integer.MIN_VALUE) is negative.
    • Floating point: IEEE 754; 0.1 + 0.2 != 0.3; NaN != NaN (use Double.isNaN); -0.0 == 0.0 but Double.compare distinguishes; casting a double outside the int range saturates to MIN/MAX, NaN → 0 (§5.1.3).
    • Shifts: the shift distance is masked (& 31 for int, & 63 for long); >> is arithmetic, >>> logical.
    • String concatenation (§15.18.1): if either operand is a String the other is converted (null → "null"); left-associative, so 1 + 2 + "x" is "3x" but "x" + 1 + 2 is "x12". Non-constant concatenation creates a new String (§12.5); constant expressions are folded and interned, so "a" + "b" == "ab" is true while new String("ab") == "ab" is false.
    byte b = 10; b += 5;           // compound assignment implies a cast: b = (byte)(b + 5)
// b = b + 5;                  // error: int cannot be converted to byte
int i = 'A' + 1;               // 66 — char promoted to int
char c = (char) i;             // 'B'
long big = 1 << 40;             // 256 (!) — int shift, distance masked to 8; write 1L << 40
System.out.println(-7 / 2 + " " + -7 % 2);    // -3 -1
System.out.println((int) 3.99e9);             // 2147483647 — saturates

System.out.println((x == y) + " " + (p == q) + " " + p.equals(q));   // true false true

    Variables and var

    Seven kinds of variables (§4.12.3): class variables (static), instance variables, array components, method parameters, constructor parameters, lambda parameters, exception parameters, local variables. final means assigned exactly once. var (§14.4, Java 10) infers a local variable's type from its initializer — it is not dynamic typing: var list = new ArrayList<String>() has type ArrayList<String> forever; var x = null is an error. Generic arrays don't exist (new List<String>[3] is illegal) because arrays are covariant and checked at run time: storing a Integer into an Object[] that is really a String[] throws ArrayStoreException — a contrast with generics that lesson 4 builds on.
